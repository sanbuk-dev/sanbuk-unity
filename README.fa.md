# Sanbuk Unity SDK

پکیج رسمی یونیتی برای [سنبوک](https://sanbuk.com) — نمایش تبلیغ در رسانهٔ ناشر، در مدل CPA.

**[English guide →](README.md)**

> **وضعیت: اولین نسخهٔ پیش‌نمایش — فعلاً فقط اندروید.** بنر، تبلیغ داخل صحنه، اینترستیشیال و پاداشی هر چهار کار می‌کنند. iOS وقتی می‌آید که لایهٔ رندر اس‌دی‌کی نیتیو iOS ساخته شود.

## نصب

**Window ← Package Manager ← + ← Add package from git URL:**

```
https://github.com/sanbuk-dev/sanbuk-unity.git
```

هیچ چیزی برای resolve کردن و هیچ تنظیمی لازم نیست. اس‌دی‌کی نیتیو به‌صورت یک فایل `.aar` ساده داخل `Runtime/Plugins/Android/` همراه پکیج سفر می‌کند، نه به‌صورت وابستگی گرِیدل — وابستگی یعنی واکشی از Google Maven یا Maven Central موقع بیلد، که روی خیلی از شبکه‌هایی که ناشران ما با آن بیلد می‌گیرند یا خیلی کند است یا اصلاً شکست می‌خورد. اس‌دی‌کی‌ای که بیلد کسی را می‌شکند، اس‌دی‌کی‌ای است که حذف می‌شود.

`kotlin-stdlib.jar` هم به همین دلیل کنارش است: اس‌دی‌کی نیتیو با کاتلین نوشته شده و یک پروژهٔ یونیتی کاتلین ندارد. هر دو فایل را سر جایشان بگذارید.

## استفاده

```csharp
void Start()
{
    Sanbuk.Init("YOUR-MEDIA-CODE");
}
```

**بنر روی بازی** — اس‌دی‌کی نیتیو می‌کشدش، دیده‌شدن را با معیار viewability می‌سنجد و کلیک را می‌برد:

```csharp
SanbukBanner.Show("HOME-TOP", SanbukBannerPosition.Bottom);
SanbukBanner.SetVisible(false);   // حین کات‌سین
SanbukBanner.Hide();              // کارتان با آن تمام شد
```

**تبلیغ داخل صحنه** — همان تبلیغ به‌شکل داده، با uGUI و فونت و قاب خودِ بازی:

```csharp
Sanbuk.LoadAd("LEVEL-END", ad =>
{
    if (ad == null) return;       // پاسخ عادی است، نه خطا

    titleText.text = ad.Headline;
    ctaText.text   = ad.CallToAction;
    labelText.text = ad.DisclosureLabel;
    StartCoroutine(LoadImage(ad.ImageUrl));

    ad.RecordImpression();        // وقتی واقعاً روی صفحه است
    button.onClick.AddListener(ad.Click);
});
```

در بازی معمولاً این تنها گزینه است، و دلیل اینکه سرور تبلیغ را **توصیف** می‌کند به‌جای فرستادن نشانه‌گذاری هم همین است. بازی روی یک سطح رندر می‌شود و هیچ layout اندرویدی ندارد که view در آن بنشیند، پس تبلیغی که قرار است روی یک تابلوی داخل دنیای شما باشد باید با کد خود بازی کشیده شود. دو تعهد همراهش می‌آید: `RecordImpression()` را فقط وقتی صدا بزنید که تبلیغ واقعاً روی صفحه است، و `DisclosureLabel` را جایی روی آن بگذارید.

**تمام‌صفحه:**

```csharp
SanbukFullscreen.Load("LEVEL-END", ad => _interstitial = ad);

// ...بعداً، هر وقت بازی شما تصمیم گرفت...
_interstitial?.Show(
    onShown:  PauseGame,
    onClosed: ResumeGame);
```

**پاداشی** — جایزه را در `onReward` بدهید و جای دیگری نه. `onClosed` چه جایزه گرفته باشد چه نه صدا زده می‌شود، پس دادن جایزه در آنجا یعنی پاداش‌دادن برای تبلیغی که رد شده است:

```csharp
SanbukFullscreen.LoadRewarded("EXTRA-LIFE", ad => _rewarded = ad);

_rewarded?.Show(
    onShown:   PauseGame,
    onClosed:  ResumeGame,
    onReward:  () => GrantExtraLife(),
    onRefused: reason => CarryOnWithout(reason));
```

`onRefused` یک خط لاگ نیست که نادیده بگیرید. قواعد قطع‌کردن — هیچ تبلیغی حین کولد استارت، هیچ تبلیغی پشت‌سرهم، سقف در هر نشست، و دکمهٔ بستن فقط بعد از چند ثانیه — در اس‌دی‌کی نیتیو هستند، پس یک نمایش می‌تواند رد شود و بازی شما باید طوری ادامه دهد که انگار اصلاً نخواسته بود.

## در ادیتور

همهٔ فراخوانی‌ها طوری جواب می‌دهند که انگار هیچ تبلیغی موجود نیست: `LoadAd` مقدار null می‌دهد، `Show` با دلیل `not_available` رد می‌کند، و بنر کاری نمی‌کند. زدن Play هیچ‌وقت به موجودبودن تبلیغ وابسته نیست، و مسیر «جایگاه خالی» — همان مسیری که بازی شما به‌هرحال باید مدیریتش کند — همانی است که حین ساخت تمرین می‌کنید.

## این پکیج چیست

عمداً یک بایندینگ نازک. مچینگ، پیسینگ، سقف تکرار، دورهٔ آزمایشی و بودجه روی سرور سنبوک هستند؛ قاعدهٔ دیده‌شدن، صف آفلاین ایمپرشن و قواعد قطع‌کردن در اس‌دی‌کی نیتیو. این پکیج می‌پرسد، می‌کشد، و گزارش می‌دهد.

بیلدی که روی استور می‌رود ماه‌ها فریز است، پس قاعده‌ای که داخل یک پوسته سفت شود از چند بار تغییر تصمیم عمر بیشتری می‌کند — و باید برای هر پوستهٔ دیگر دوباره نوشته شود، جایی که نسخه‌ها از هم دور می‌افتند.

## نکته‌های انتشار

- **IL2CPP:** فایل `link.xml` داخل پکیج هست. کلاس‌های اس‌دی‌کی با نام صدا زده می‌شوند، پس بدون این فایل لینکر حذفشان می‌کند و خطا **فقط در بیلد ریلیز** ظاهر می‌شود.
- **ترد:** همهٔ کال‌بک‌ها روی ترد اصلی یونیتی به شما می‌رسند. از داخل هرکدامشان می‌توانید صحنه را دست بزنید.
- **پرمیشن:** اس‌دی‌کی نیتیو فقط `INTERNET` و `ACCESS_NETWORK_STATE` اعلام می‌کند و بس. نه موقعیت مکانی، نه وضعیت تلفن، نه advertising id.
- **هم‌زیستی با بقیه:** هیچ کلاس، منبع یا نام پرمیشن مشترکی با تپسل، ادیوری یا AdMob ندارد، پس کنار هر چیزی که از قبل دارید می‌نشیند.

## بررسی پکیج

هیچ‌کدام از این دو بررسی به لایسنس فعال یونیتی نیاز ندارد، پس یک کلون تازه و یک ماشین CI هم می‌توانند اجرایشان کنند:

```bash
Tests/compile.sh          # کامپایل Runtime و نمونه با خودِ Roslyn یونیتی
python3 Tests/verify_jni.py   # تطبیق هر نام جاوایی که این C# به زبان می‌آورد با فایل aar
```

دومی از آنچه به نظر می‌رسد مهم‌تر است. سی‌شارپ هر رشته‌ای را که به `AndroidJavaObject` بدهید با خوشحالی کامپایل می‌کند، پس نام کلاس اشتباه یا گتر تغییرنام‌داده اصلاً خطای بیلد نیست — کرش روی گوشی یک بازیکن است، روی همان یک صفحه‌ای که تبلیغ نشان می‌دهد. همین حالا یکی را گرفته: `Sanbuk.Init` یک `SanbukConfig` با دو آرگومان می‌ساخت، در حالی که سازندهٔ تولیدشده سه‌تا می‌گیرد.
